# MindHive Python Patterns

How src/mindhive modules are actually built: an event-sourced core, pure
analysis pipelines, and a CLI that registers everything the same way.

## When to Activate

- Adding or modifying a module under `src/mindhive/`
- Designing a new `hive` subcommand or extending an existing one
- Writing code that reads the event ledger or one of its projections
- Adding a new analyzer/report feature (the `hive context` / `hive packs` family)
- Reviewing a PR that touches store reads, dataclasses, or CLI wiring
- Deciding whether something belongs in an event, a projection, or a sidecar config

## The store: one event shape, forever

The store is an append-only event ledger under `~/.mindhive/<namespace>/events/`
(one JSONL segment file per session). Every event is one canonical JSON object:

```python
# The invariant shape every append surface produces and every reader assumes.
{
    "ts": "2026-07-21T13:38:44Z",     # UTC, second precision
    "session_id": "manual",           # segment key; inherit MINDHIVE_SESSION
    "type": "code_change",            # MUST be registered in events.py
    "payload": {...},                 # contract owned by the writing module
    "tags": ["auto", "harvest"],      # lowercase-kebab, existing taxonomy
}
```

Three rules follow from append-only:

```python
# 1. Corrections are NEW events, never edits. The hash chain (hive verify)
#    exists to prove nobody rewrote history — an "edit" would break it.
# 2. The payload contract lives in the module that writes the type
#    (changelog.py owns code_change, sop.py owns sop_*).
# 3. New event types follow docs/DATA_MODEL.md §6: register with a
#    why-comment, validate at the append surface, decide merge exemptions,
#    choose projections deliberately, test, then record the change-log entry.
```

Everything else on disk — `STATE.md`, `BRIEFING.md`, `MEMORY.md`, graph blobs —
is a rebuildable projection of the ledger. If a file cannot be regenerated by
replaying events, it is not a projection; it is operator config and belongs in
a sidecar (see below).

## Total reads: a malformed row never takes down a reader

The ledger contains history written by every past version of this code. Readers
therefore never trust a row:

```python
# events.read_all() is TOTAL: it skips malformed/torn rows instead of raising.
# One corrupt line used to take down every CLI command AND every dashboard
# section at once. Corruption is surfaced loudly by `hive verify`
# (corrupt_rows + hash mismatch), not by crashing readers.
for event in events.read_all():
    ...  # every event here is guaranteed well-formed
```

The same totality applies to every filesystem walk. `context._read_text` is the
canonical helper shape:

```python
def _read_text(path: Path) -> str | None:
    """Read a file as text, or None if it cannot be read at all.
    errors="replace" keeps invalid UTF-8 measurable rather than fatal."""
    try:
        return path.read_text(encoding="utf-8", errors="replace")
    except Exception:
        return None
```

A collector that meets a broken file reports what it could read and moves on.
`packs.collect_pack` goes one step further for *declared* inputs: a missing
SKILL.md is a Finding (a real defect), not an exception — the run always
completes and always renders a report.

## Projections and folds

Projections are pure folds over `read_all()` output. The pattern:

```python
def project_state(events_iter) -> dict:
    state = {"lessons": [], "decisions": []}
    for ev in events_iter:                  # fold — no I/O inside
        if ev.get("type") == "caveat":
            state["lessons"].append(ev["payload"].get("text", ""))
    state["lessons"] = state["lessons"][-LESSONS_CAP:]   # cap at delivery
    return state
```

Two hard-won caps rules:

```python
# Item-count caps (LESSONS_CAP=10, DECISIONS_CAP=5, _TIMELINE_CAP=40) bound
# HOW MANY, not HOW BIG. STATE.md reached 37 KB while nominally "capped".
# Any new delivery surface needs a SIZE bound too — hive context exists
# precisely because nothing measured bytes. Check your feature's output
# against `hive context` before shipping it into an auto-loaded artifact.
```

## Operator config is a sidecar, not an event

Some values are not rebuildable from history because they are *decisions the
operator made*: the context token budget, enforce-rule overrides, pack gate
thresholds. Those live in small JSON sidecars beside the namespace artifacts:

```python
# context.py — the exemplar sidecar (context_budget.json):
BUDGET_FILE = "context_budget.json"

def load_budget(project=None) -> int | None:
    """Fail-open: a missing, corrupt, or non-positive value reads as no
    budget."""
    try:
        obj = json.loads((paths.project_dir(project) / BUDGET_FILE)
                         .read_text(encoding="utf-8"))
        budget = obj.get("budget") if isinstance(obj, dict) else None
        ...
    except Exception:
        return None

def save_budget(budget: int, project=None) -> dict:
    paths.write_text_atomic(paths.project_dir(project) / BUDGET_FILE, ...)
```

`paths.write_text_atomic` is mandatory for sidecar writes — a torn write to a
config file must not exist as a state. `docs/packs/packs.json` follows the same
philosophy at repo scope: thresholds are data, never code constants.

## The four-stage analyzer pipeline

Every read-only report feature is the same machine, proven twice
(`context.py`, then `packs.py`):

```python
# Stage 1  collect_*()   — the ONLY stage that touches the filesystem.
#                          Injectable roots (home=..., skills_root=...) so
#                          tests never read real state.
# Stage 2  analyze()     — totals, ranking, stable ordering. Pure.
# Stage 3  findings()/gates — rule functions, each independent, each
#                          returning zero or more Finding rows. Pure.
# Stage 4  render_text()/to_json() — presentation only. Pure.
```

The pipeline currency is a frozen dataclass. `context.Segment` and
`packs.PackFile` both freeze at collection time:

```python
@dataclass(frozen=True)
class Segment:
    name: str
    origin: str          # "hive" | "claude"
    path: str            # "" when not a single file
    nbytes: int
    tokens: int
    kind: str
    detail: str = ""
```

Why frozen: stages 2–4 can never mutate what stage 1 measured, so a report is
reproducible by construction. Determinism is a stated contract — `analyze`
sorts with explicit tiebreaks ("a report that reshuffles itself is useless for
spotting real change") and `to_json` uses `sort_keys=True`. The test suite
pins this: `test_to_json_is_parseable_and_stable` in `tests/test_packs.py`
asserts two runs render byte-identical JSON.

Adding a new source to an analyzer means adding a collector and its CLI
wiring; stages 2–4 must not change. If they must, the feature is not a new
source — it is a new analyzer.

## Findings, not exceptions; severity is a contract

Rule results are data:

```python
@dataclass(frozen=True)
class Finding:
    rule: str        # stable machine-readable id ("depth-floor")
    severity: str    # packs: "error"|"warn"; context: "high"|"medium"|"low"
    subject: str
    message: str     # human sentence with the numbers IN it
```

The severity vocabulary is part of the feature's contract: `hive packs check`
exits 1 only on `"error"`. Never invent a new severity in a message string —
downstream tooling switches on it.

## CLI subcommand registration

One pattern, ~40 commands, zero exceptions:

```python
# handler: cmd_<name>(args) -> int | None   (None means exit 0)
def cmd_packs_check(args) -> int | None:
    from . import packs as packs_mod        # lazy import — keeps `hive -h` fast
    report = packs_mod.analyze(...)
    print(...)                              # print(), never a logging framework
    return None if report.get("ok") else 1

# registration inside _build_parser():
pk = sub.add_parser("packs", help="stack content pack quality gates (read-only)")
pksub = pk.add_subparsers(dest="packs_cmd", required=True)   # group form
pkc = pksub.add_parser("check", help="run all gates; exit 1 on error findings")
pkc.set_defaults(func=cmd_packs_check)
```

Flat commands (`hive context`) attach `set_defaults` directly; families with
verbs (`review`, `sop`, `log`, `packs`) use the group form. Exit codes are
meaningful and documented in the handler docstring: `hive context --check`
returns 1 for over-budget and 2 for check-without-budget, and scripts gate on
exactly those numbers via `$LASTEXITCODE`.

## Paths and namespace hygiene

```python
# ALWAYS resolve through paths.py — never hand-build ~/.mindhive paths.
pdir = paths.project_dir(project)        # respects MINDHIVE_HOME/_PROJECT

# Worktree trap: from a linked worktree, Path.cwd() encodes to the WORKTREE
# path, but per-project artifacts key on the MAIN repo folder. Resolve like
# context._memory_folder does: `git rev-parse --git-common-dir` names the
# main repo's .git even from a worktree. For "which checkout am I validating"
# (packs), --show-toplevel is correct instead: the worktree IS the target.
```

Namespace discipline: 48 namespaces exist on this machine because runs from
odd directories mint fresh ones. A freshly-minted-namespace warning means the
operation is about to land in a brand-new empty store — stop and pin
`MINDHIVE_PROJECT` instead.

## The stdlib-only constraint

`pyproject.toml` declares `dependencies = []` — deliberately. Consequences:

```python
# - No PyYAML: frontmatter uses plugins._parse_frontmatter, a documented
#   hand parser that FLATTENS keys and folds `>-` block scalars.
# - No tokenizer: context.estimate_tokens is a chars/4 heuristic, documented
#   as the single swap point if precision ever justifies a dependency.
# - No requests/rich/click: urllib, print(), argparse.
# Anything needing a third-party package must live OUTSIDE src/mindhive
# (a script, a skill, a hook) — the core must import clean on any Python.
```

## The delivery pipeline: recall over paste

Between the store and a session sits a delivery chain, and every stage of it
is bounded on purpose:

```python
# ledger -> recall (ranked retrieval)  -> briefing/STATE (capped sections)
#        -> MEMORY.md (auto-loaded)    -> the session's context window
```

Design rules the chain enforces, each with a measured reason:

```python
# Deliver the FEW most relevant items, never everything: recall > paste.
#   The auto-loaded surface was measured at ~16,000 est. tokens before the
#   budget work — every byte here is paid at the start of EVERY session.
# Dedup before delivery: consolidation folds reworded repeats into
#   survivors (append-preserving — originals stay on disk; briefings show
#   survivors). One decision was found appended 9 times; caps alone cannot
#   fix that, dedup can.
# Pinned beats recent: safety-critical caveats tagged pinned survive cap
#   rotation; recency is a ranking signal, not a retention policy.
# Every delivery surface states its cap NEXT TO the code that applies it —
#   a cap nobody can find is a cap nobody maintains.
```

When adding a feature that feeds this chain, the question is never "should
this be delivered?" but "which stage bounds it, and what does `hive context`
say it costs?"

## Registering a new event type, end to end

The extension procedure (docs/DATA_MODEL.md §6) as it looks in code. Worked
example — a hypothetical `pack_validated` audit event:

```python
# 1. events.py — register WITH a why-comment (unregistered types are
#    rejected at the append surface; the registry IS the allowlist):
DETERMINISTIC_TYPES = {
    ...,
    "pack_validated",   # packs.py: gate outcome audit; never merged
}

# 2. The owning module validates its own payload contract at append time:
def record_validation(report: dict) -> None:
    payload = {"ok": bool(report["ok"]),
               "errors": int(...), "manifest": str(...)}
    events.append(type="pack_validated", payload=payload,
                  tags=["auto", "packs"])

# 3. Merge exemption: audit/registry types never merge — consolidation
#    must not fold two validation runs into one "survivor".
# 4. Projection decision: does STATE/briefing show it? Deliberately chosen,
#    not defaulted — most audit types stay recall-only.
# 5. Tests: append accepts the contract, readers fold it, malformed
#    payloads are skipped not raised.
# 6. The change-log entry records the addition (the verification file's
#    Phase 6 blocks on it).
```

Steps 3–5 are where reviews catch real bugs: a new type that merges, or
that floods STATE.md, damages surfaces the author never looked at.

## Rendering conventions

Report-shaped output follows three rules, visible in both analyzers:

```python
# 1. Deterministic ordering everywhere a human compares runs:
ranked = sorted(segs, key=lambda s: (-s.tokens, s.name))   # explicit tiebreak
findings.sort(key=lambda f: (order[f.severity], f.rule, f.subject))

# 2. Numbers live IN the message, pre-formatted — a finding must be
#    quotable into a PR body without re-deriving anything:
f"{s.name} is {s.nbytes:,} bytes (~{s.tokens} est. tokens), past the ..."

# 3. Read-only commands SAY so, last line, every time:
"This command is read-only and changed nothing."
#    Estimates are labelled as estimates; a report that implies precision
#    it does not have gets trusted wrong.
```

`to_json` mirrors `render_text` from the same report dict — never two
divergent computations of the same numbers — and keeps `sort_keys=True` so
diffs of saved reports show real change only.

## Module docstring house style

Every module opens with a `# src/mindhive/<name>.py` comment line and a long
docstring that explains *why the module exists and what invariants it holds*,
not just what it does — see the top of `context.py` or `packs.py` for the
tone. A reader must be able to review a change against the docstring alone.

Function docstrings state contracts ("Total: problems become findings") and
name their failure philosophy (fail-open vs fail-closed) explicitly, because
the sibling security file's decision table depends on that being written down.

## Anti-patterns with recorded incidents

Each of these was found in this codebase or its inputs, which is why the
rules above exist:

```text
Re-reading a file per rule           -> each artifact was read three times
                                        in one findings pass; read once,
                                        share the text dict across rules.
Item caps standing in for size caps  -> STATE.md at 37 KB while "capped".
Hand-built store paths in tests      -> escapes isolation; touches the
                                        live ledger (paths.project_dir).
Raising on a malformed row           -> one torn line took down every
                                        command and dashboard section.
Thresholds as code constants         -> invisible to operators, untunable
                                        without a release; manifest data.
Unregistered event types             -> refused at append; the registry
                                        is the allowlist, not a suggestion.
```

## Quick Reference

| Mechanic | Use |
|---|---|
| `events.read_all()` | total ledger read — malformed rows skipped, never raised |
| canonical event dict | `ts / session_id / type / payload / tags`, type registered in events.py |
| projection fold | pure function over events; caps applied at delivery |
| sidecar + `write_text_atomic` | operator config (budgets, thresholds) — not rebuildable, not an event |
| `@dataclass(frozen=True)` | pipeline currency; collection measures once, stages never mutate |
| collect → analyze → findings → render | the four-stage analyzer; only collect touches disk |
| `Finding(rule, severity, subject, message)` | machine-readable rule results; severity is a contract |
| `cmd_x(args) -> int \| None` + `set_defaults(func=...)` | CLI handler + registration; lazy imports |
| `paths.project_dir()` / `--git-common-dir` | namespace + worktree-safe path resolution |
| `dependencies = []` | stdlib only; hand parsers and heuristics are deliberate |
