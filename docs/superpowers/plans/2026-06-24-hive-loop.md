# hive loop Implementation Plan (executed 2026-06-24)

**Goal:** Add a native `hive loop` command that drives the headless Claude Code CLI
iteratively until a task is complete, seeded by MindHive memory and bounded by real
token/cost/context safeguards.

**Architecture:** A new `src/mindhive/loop/` package. Pure modules (config, contract,
budget, context, safeguards, task, progress, prompt, state) are fully unit-tested with
table-driven cases; `driver.py` is the only boundary to the real `claude` CLI and is
faked in tests; `engine.py` wires the cycle and emits `loop_*` events through the
existing `events` ledger. No new runtime dependencies (stdlib `tomllib`, `subprocess`,
`shutil`).

**Tech Stack:** Python ≥3.11, pytest, stdlib only. Integrates with existing
`mindhive.events`, `mindhive.briefing`, `mindhive.recall`, `mindhive.guard`,
`mindhive.paths`.

## Conventions

- Tests live in `tests/test_loop_<module>.py`. Store-touching tests set
  `MINDHIVE_HOME=tmp_path` and `MINDHIVE_PROJECT=test`.
- All new event types are registered in `events.DETERMINISTIC_TYPES`.
- Pure functions take `now` (epoch seconds, `float`) as an argument — never call
  `time.time()` inside them — so tests are deterministic.

## Deviation from the original plan

- `tests/test_loop_engine.py::test_loop_context_resets_when_window_half_full` used
  `progress_fn=lambda i: True` and never checked the fix_plan box, so the unchecked
  required item made the dual-condition exit gate correctly refuse to exit at
  iteration 2 (the loop ran a third time and exhausted the fake driver). The engine
  was correct; the test was fixed to check the box before iteration 2 — mirroring the
  pattern the plan itself uses in `test_loop_completes_on_dual_condition` — preserving
  the test's intent (verify the session resets to `None` after a bloated iteration).

## Notes / decisions

- New event types are **deterministic** (no API cost) — stay out of the semantic
  LEDGER/graph but show in activity, consistent with `file_touched`/`compaction`.
- The context-reset reuses the existing `compaction` event type so the dashboard/graph
  render it with no extra work.
- Pure modules never read the clock; `engine.run_loop` takes
  `now_fn`/`sleep_fn`/`progress_fn` injectables — this makes the whole loop testable
  without a real CLI or wall-clock waits.
- Budget gating lives in the engine (Task 12) on top of the pure math (Task 5), so the
  cap policy (`pause`/`stop`) is in one place.
