Five golden rules (spec 9.3). The long form, with what in the code enforces each rule and what does not: docs/SOP_FIVE_GOLDEN_RULES.md.

1. Absolute honesty. Never report a task as done, passing or fixed without execution evidence from a real run: a `verification` event only `verify.run_and_record` can stamp, and a pytest tail that was actually read. A tool error or a failing test is reported plainly, with its traceback. The lintester gate is fail-closed: a unit no test names is refused, a new module is refused with the exact test file to write.

2. Zero-assumption grounding. Before answering about project state or starting work, read the record: `hive state` (STATE.md) or `hive recall "<query>" --semantic`. Never rebuild history, paths or the reasons behind past decisions from conversation memory; when the ledger does not have it, say so. `hive premise check [--file F]` checks a handoff's asserted paths, roadmap ids and test counts against the record.

3. Work-session and initiative tags. Tie every change to a work-session tag naming the method, `[WS: <phase> | <action> | <UTC timestamp>]`, recorded with `hive worksession record --phase <phase> --action <catalog key or text>`. Work taken on beyond the user's specification carries `[INITIATIVE: <technical reason> | Ref: <incident>]` (`--initiative --reason "..." --ref "..."`). The code provides the tags and the Oversee cards show them; no hook records a step per edit.

4. Context budget and smart rotation. Before a large task run `hive context --check`: it measures the auto-loaded surface against the namespace budget and the MEMORY.md loader cuts, exit 1 when over budget or cut with no rollover notice. Live occupancy is the Stop hook's job (`hooks/stop.ps1`, `hooks/stop.sh`, `rotation/hook.py`): past min(MINDHIVE_ROTATION_CAP, MINDHIVE_ROTATION_RATIO x window), 100,000 tokens on a 200k window, it writes ROTATION_PENDING and `hive session run` starts a successor. The hook is inert unless MINDHIVE_ROTATION is set, which only `hive session run` does.

5. Mandatory code change-log. Record every change to src/mindhive/ or tests/, however small, before calling the task done: `hive log <update|minor_change|deletion|reduction|major_change|replacement> "<a real sentence, at least 10 characters>" [--files ...]`. Entries are `code_change` events; `session_end` queues any unlogged source file into a pending marker that STATE.md and the briefing show until the entry is written.
